1. Pengenalan Project & Skenario Bisnis

A. Apa itu Website Nazelle Délices?

Nazelle Délices adalah sistem informasi dan aplikasi web e-commerce manajemen toko roti dan kue artisan Prancis (French Pâtisserie & Boulangerie) yang berbasis di Senopati, Jakarta Selatan. Aplikasi ini mengintegrasikan seluruh operasional toko roti fisik ke dalam satu ekosistem web yang modern.

💡 Analogi Sederhana untuk Pemula:
Bayangkan Nazelle Délices seperti gedung toko roti fisik berlantai dua:
  • Lantai 1 Depan: Etalase tempat pembeli umum melihat croissant hangat, mengecek stok, dan memesan.
  • Meja Kasir: Tempat kasir toko melayani transaksi langsung dengan cepat dan mencetak nota struk belanja.
  • Dapur & Gudang Belakang: Tempat baker dan staf mencatat pasokan bahan baku (tepung, mentega Prancis) dari supplier.
  • Ruang Kantor Pemilik: Tempat Ibu Pemilik Toko (Madame Nazelle) melihat laporan keuntungan dan grafik penjualan.
Semua aktivitas tersebut digabungkan ke dalam satu sistem web yang otomatis dan saling terhubung.

B. Masalah Nyata yang Diselesaikan Sistem

Masalah di Toko Tradisional Solusi di Project Nazelle Délices
Overselling (Stok Habis Tetap Terjual): Pelanggan memesan 5 kue, padahal sisa di rak tinggal 2. Pessimistic Locking (lockForUpdate): Sistem mengunci data di database saat transaksi berlangsung. Jika stok kurang, pesanan langsung ditolak secara aman.
Kecurangan Harga (Client-side Hack): Pembeli nakal mengubah harga kue Rp 28.000 jadi Rp 1.000 via Inspect Element browser. Zero-Trust Server Price: Total bayar tidak dipercaya dari browser, melainkan dihitung ulang 100% di server dari database resmi.
Data Nyangkut saat Error (Inkonsistensi): Uang tercatat masuk tetapi stok gagal dipotong karena koneksi putus. Atomic Transaction (DB::transaction): Menganut prinsip All-or-Nothing. Jika ada satu item gagal, seluruh mutasi dibatalkan (rollback).
Kebocoran Hak Akses: Pembeli biasa iseng mengetik URL admin /users untuk membajak akun. Middleware (EnsureAdmin): Server memblokir request dan merespons dengan HTTP Status 403 Forbidden.

2. Penjelasan Seluruh Halaman Website

1. Halaman Beranda Publik (/ atau /beranda)

Pintu gerbang utama website yang dapat diakses siapa saja tanpa harus login. Menampilkan identitas brand Prancis, tagline "A Little Taste of Elegance", 3 keunggulan bahan baku (Mentega Prancis AOP, Fermentasi 36 Jam, Panggang Segar Setiap Pagi), serta etalase 6 kreasi produk unggulan.

Poin Penting untuk Dosen:
Kartu produk di halaman Beranda sengaja dibuat murni informatif (menampilkan foto, kategori, sisa stok, nama, dan harga) tanpa tombol pesan langsung. Pemesanan difokuskan di dalam halaman katalog setelah pelanggan login untuk menjamin keamanan pesanan.

2. Halaman Masuk / Login (/login)

Tempat pengguna memasukkan email/username dan kata sandi. Dilengkapi fitur ikon mata (👁️) untuk mengintip kata sandi. Sistem memvalidasi password menggunakan algoritma Hash::check() ke database. Tidak ada tombol jalan pintas (no bypass login) demi memenuhi standar keamanan.

3. Halaman Pendaftaran Pelanggan (/register)

Pendaftaran akun publik yang otomatis menetapkan peran sebagai role: customer. Kolom role disembunyikan agar pihak asing tidak bisa mendaftarkan diri sebagai Admin toko.

4. Halaman Katalog Toko & Pemesanan (/katalog atau /menu)

Etalase belanja interaktif lengkap dengan filter kategori (Viennoiserie, Sourdough, Patisserie, Cakes, Savory, Coffee) dan pencarian instan (live search). Setiap kartu produk memiliki tombol kuning "+ Pesan" yang memasukkan item ke panel Slide-over Drawer Cart di sebelah kanan layar.

5. Panel Keranjang Belanja & Formulir Checkout

Menghitung subtotal otomatis saat kuantitas ditambah atau dikurangi. Menyediakan input nama pemesan, catatan pesanan, serta 3 pilihan metode pembayaran:

  • QRIS: Pembayaran instan via scan kode QR digital.
  • Transfer Bank: Pembayaran ke nomor rekening resmi butik Nazelle Délices.
  • Bayar di Kasir: Pembayaran tunai langsung saat mengambil roti di butik.

6. Faktur Nota Pesanan & Simulasi Pembayaran (/sales/{sale}/invoice)

Halaman nota belanja resmi berformat struk kasir (*print-ready receipt*). Memuat nomor nota unik (contoh: INV-20261027-0001), tanggal transaksi, dan rincian item.

Fitur Simulasi Pembayaran Akademik:
Pada halaman faktur, tersedia tombol "Simulasi Pembayaran (Uji Coba UTS)". Saat ditekan, sistem secara instan memverifikasi transaksi, mengubah status menjadi "Pembayaran Berhasil", mencatat tanggal/jam pelunasan, dan menerbitkan kode referensi unik (contoh: SIM-A8F2C1D4).

7. Halaman Kasir POS Toko Roti (/sales/create)

Khusus digunakan oleh Staff Kasir untuk mencatat penjualan di kasir fisik. Kasir cukup mengklik kartu gambar roti, memasukkan nominal uang tunai yang diterima, dan kalkulator kasir akan otomatis menghitung uang kembalian pembeli.

8. Halaman Restock Pembelian Bahan (/purchases/create)

Formulir multi-item dinamis untuk mencatat pembelian pasokan bahan baku dari supplier (misal: tepung T55, mentega Normandia). Stok produk di database otomatis bertambah (increment) seketika saat disimpan.

5. Bedah Kode Kunci (Line-by-Line Code Walkthrough)

A. Jantung Transaksi Checkout & Anti-Overselling

Lokasi File: app/Http/Controllers/StorefrontController.php (Method: checkout)

// 1. Membungkus seluruh operasi ke dalam transaksi database atomik
$sale = DB::transaction(function () use ($validated, $request) {
    
    // 2. Buat header nota penjualan baru
    $sale = Sale::create([
        'user_id'        => Auth::id() ?? 1,
        'sale_number'    => $this->generateSaleNumber(),
        'customer_name'  => $validated['customer_name'],
        'payment_method' => $validated['payment_method'] ?? 'cashier',
        'payment_status' => 'unpaid',
        'status'         => 'completed',
        'sold_at'        => Carbon::now(),
    ]);

    $grandTotal = 0;

    foreach ($validated['items'] as $itemData) {
        // 3. PESSIMISTIC LOCKING: Kunci baris database agar tidak dibeli orang lain
        $product = Product::lockForUpdate()->findOrFail($itemData['product_id']);
        $qty = (int) $itemData['quantity'];

        // 4. Pengecekan sisa stok: cegah stok menjadi minus
        if ($qty < 1 || $product->stock < $qty) {
            throw ValidationException::withMessages([
                'items' => "Stok '{$product->name}' tidak mencukupi. Sisa: {$product->stock} pcs."
            ]);
        }

        // 5. ZERO-TRUST PRICE: Ambil harga resmi langsung dari database server
        $unitPrice = (float) $product->selling_price;
        $subtotal = $unitPrice * $qty;

        $sale->items()->create([
            'product_id' => $product->id,
            'quantity'   => $qty,
            'unit_price' => $unitPrice,
            'subtotal'   => $subtotal,
        ]);

        // 6. Potong stok produk secara seketika
        $product->decrement('stock', $qty);
        $grandTotal += $subtotal;
    }

    $sale->update(['total' => $grandTotal]);
    return $sale;
});
Cara Menjelaskan ke Dosen:
"Method checkout() ini dirancang dengan standar enterprise: pertama, DB::transaction menjamin konsistensi ACID (all-or-nothing); kedua, Product::lockForUpdate() mencegah race-condition saat web diakses ramai; dan ketiga, harga dihitung di server dari database resmi untuk mencegah manipulasi harga dari browser."

6. Arsitektur & Siklus Data Database

A. 8 Tabel Utama & Fungsinya

Nama Tabel Fungsi & Data yang Disimpan
users Menyimpan akun pengguna (nama, email, hash password, dan role: admin, staff, customer).
categories Klasifikasi menu (Viennoiserie, Sourdough, Patisserie, Cakes, Savory, Beverages).
products Katalog kue (SKU unik, nama, deskripsi, harga beli, harga jual, stok, batas minimum).
suppliers Data distributor pemasok bahan (tepung terigu T55, mentega Prancis, cokelat Valrhona).
purchases & purchase_items Mencatat nota restock pasokan bahan baku dari supplier yang menambah stok produk.
sales & sale_items Mencatat nota pesanan penjualan kasir maupun toko online yang memotong stok produk.

B. Relasi Antarmodel Eloquent

  • Category hasMany Product • Product belongsTo Category
  • Sale hasMany SaleItem • SaleItem belongsTo Sale
  • User hasMany Sale • Sale belongsTo User
  • Supplier hasMany Purchase • Purchase belongsTo Supplier

9. Prediksi Pertanyaan Dosen & Jawaban Mantap

Q1: Mengapa kamu memilih framework Laravel daripada PHP Native?
Jawaban: "Laravel menyediakan struktur arsitektur MVC yang rapi, keamanan bawaan terhadap CSRF dan SQL Injection, manajemen database terstruktur via Migration dan Eloquent ORM, serta dukungan 24 automated unit tests yang menjamin aplikasi bebas bug saat dideploy ke produksi."
Q2: Bagaimana sistem mencegah terjadinya overselling saat stok kue hampir habis?
Jawaban: "Kami menggunakan teknik Pessimistic Locking dengan perintah Product::lockForUpdate() di dalam DB::transaction(). Ketika pelanggan memproses pesanan, baris produk di database dikunci sementara waktu sehingga jika ada pelanggan lain yang memesan di detik yang sama, sistem memeriksa ketersediaan stok terlebih dahulu sebelum memotongnya."
Q3: Bagaimana cara sistem membedakan hak akses Admin, Staff, dan Pelanggan?
Jawaban: "Melalui kolom role pada tabel users yang diproteksi oleh Middleware (EnsureAdmin dan EnsureStaff). Jika user pelanggan mencoba membuka URL admin /users, middleware langsung mencegat request dan mengembalikan HTTP Status 403 Forbidden."
Q4: Mengapa total harga tidak dihitung dari JavaScript di browser?
Jawaban: "Menerapkan prinsip Zero-Trust Client Input. Kode JavaScript di browser dapat diedit dengan Inspect Element oleh hacker untuk memanipulasi harga. Karena itu, browser hanya mengirimkan ID produk dan jumlah, lalu server mengambil harga resmi langsung dari database dan menghitung total secara independen."
